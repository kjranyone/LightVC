# 官能評価と「萌え」のパラメタ化：人間が仕上げるリアルタイムVC

> status: PROPOSED（評価・制御・UXの横断設計。ネットワーク採用ではない）
> 作成: 2026-09-08
> 起点: オーナーとの研究相談。「良い・悪い」と学習改善のギャップ、および距離感・喉の鳴り方を人間が調整する再生側UX。
> 前提: [README](README.md)、[RESEARCH](RESEARCH.md)、[Y-S1設計](causal_codec.md)。本書の実験・制御効果は未検証。

## 1. この研究で実現したいこと

自分の望む声で、その場で人と話せることに価値がある。リアルタイム性は、その声を自分の発声として扱う体験の要件である。収益性とは別に、この体験によって幸せになる人がいることを研究の動機に置く。

目標は、機械が決めた一種類の「萌え声」を出すだけでなく、生成された声を人間が聴き、距離感、息、喉の質感、響き、抑揚を調整し、「この声で話したい」と思える状態へ仕上げられるVCである。

現行の自動萌え方針は維持する。中立な発声にも機械が表現を付与し、その付与量と質を人間が調整する。操作者が最初から目的の演技を完成させることを前提にしない。

本書では「再生側」を、まず操作者が変換出力をモニターして調整する層と定義する。受信者ごとの独立した再変換・配信プロトコルまでは今回の設計範囲に含めない。

## 2. 官能評価のギャップへの答え

人間が「良くない」と判断できても、原因を言語化できるとは限らない。それは評価の不備ではない。主観評価は目的への適合を答え、実験設計は変更と結果の関係を調べる。この二つを研究側が接続する必要がある。

「悪い理由を説明してください」を改善ループの必須入力にしない。変更点を管理した候補を比較し、A / B / 同等 / 両方不合格で答えられるようにする。bad tagと自由記述は任意とする。既存READMEのA/B記録形式を基礎とし、本書はbad tagが得られなくても進められる手順を提案する。

### 2.1 三つの問いを分ける

| 問い | 人間への問いかけ例 | 役割 |
|---|---|---|
| 差の知覚・制御方向 | どちらが近く聞こえるか／違いは分からないか | ノブの意味が音として成立しているか |
| 選好 | この場面でどちらの声を使いたいか | 個人・場面に適した設定を探す |
| 受容性 | この声で話し続けたいか／両方まだ使いたくないか | 製品候補としての合否を判定する |

「息が増えた」は「良くなった」を意味しない。「AがBより良い」も「Aが合格」を意味しない。方向・好み・合否を一つのスコアに混ぜない。

### 2.2 選択だけから改善へ進む手順

1. 研究側が仮説を一つ決め、変更前後の候補を作る。同じ入力、target、生成乱数、再生条件を可能な限り共有する。
2. 短い区間をランダムな提示順で比較する。モデル名や期待する勝者は聴取中に見せない。
3. 人間は選択だけを返す。理由はなくてよい。疲れたら中断できる。
4. 研究側が条件への追従、他軸の変化、実装・計測の不整合を調べ、勝敗の帰属を絞る。
5. 別発話・別セッションで再確認する。確率生成では複数seedでも確認し、偶然よい一生成を昇格させない。
6. 受容性と実際のライブ発声を確認してから採用へ進む。

単一ノブでも複数の音響量が動くため、選好だけから物理的原因を一意に断定しない。全部不合格なら、共通の欠陥、変化幅不足、基礎品質不足を疑う。同じ候補群への評価を繰り返し要求せず、研究側で比較の作り方を変える。

### 2.3 話者類似度の位置づけ

話者類似度は目標話者への近さを確認する補助であり、萌え、心地よさ、主体感、疲れにくさの代替にはならない。VCの評価でも自然さと話者類似度は別に扱われ、客観指標と知覚の不一致が研究課題となっている。[VCC 2020](https://arxiv.org/abs/2008.12527)、[MOSNet](https://arxiv.org/abs/1904.08352)

内容保持、話者性、アーティファクト、制御効力、遅延を別々に記録する。SECSを上げるために発音や質感を犠牲にした結果は成功にしない。意図した声質編集で話者指標が変動する場合も、人間の同一性判断と併記し、単一閾値で編集を全面禁止しない。

## 3. 「萌え」は制御可能な空間と、その中の個人的な好みとして扱う

設計仮説として、萌えを普遍的な一つの音響値へ還元しない。距離感、発声の質、共鳴、抑揚などを操作できる空間を作り、その中で個人と場面に合う組み合わせを選ぶ。

三層を明示する。

| 層 | 例 | 意味 |
|---|---|---|
| 音響観測・制御量 | F0、スペクトル傾斜、帯域別非周期成分、反射音の利得 | 測定・合成で扱う量。すべてが直接操作可能とは限らない |
| 知覚的な操作軸 | 高さ、息、芯、きしみ、響き、近さ | 人間が聴いて方向を理解するノブ |
| 好み・場面の設定 | 親密、柔らかい、元気、自分にとっての萌え | 複数ノブと時間変化を束ねたプリセット |

観測量とノブは一対一対応を仮定しない。H1–H2やCPPなどは発声に関連するが、複数の要因の影響を受ける。単一指標を「息の真値」や「声門閉鎖の真値」にしない。[Shue et al., 2010](https://www.isca-archive.org/interspeech_2010/shue10_interspeech.html)

知覚的な声質を例示から連続制御するTTS研究もある。ただし、それは本プロジェクトの因果VC・低遅延・萌えへの有効性を証明するものではない。[Rautenberg et al., 2025](https://arxiv.org/abs/2501.08791)

## 4. 制御候補の定義

以下は初期の操作的定義であり、人体の状態を音声から確定するものではない。UIの0〜1は物理単位ではなく、音声で検証した範囲内の相対位置とする。各軸に基準音と両端の音を用意し、名前より先に聴き分けられるかを確認する。

| 操作軸 | 初期の意味 | 音響量・観測候補 | 主な接続先と注意 |
|---|---|---|---|
| 高さ | 声の音高の基準 | 有声部log-F0、半音差、追従誤差 | prosody。声の小ささ・可愛さとは別 |
| 抑揚 | 高さの動きの大きさ | log-F0の変化量・傾き、イベント応答 | 因果prosody policy。発話全体統計をruntimeで使わない |
| 息 | 有声に混じる息の質感 | 帯域別非周期成分、HNR、CPP、補正H1–H2 | texture条件。単純な白色雑音加算で成立したことにしない |
| 芯・張り | 輪郭のはっきりした発声感 | スペクトル傾斜、倍音分布、立ち上がり | style/texture条件。音量・息・高さの変化と切り分ける |
| きしみ・粒立ち | 意図したcreakyな発声イベント | 不規則周期、subharmonic、creak出現区間 | イベント条件。全区間へのjitter付与と同一視しない |
| 響きの大きさ | 声道の共鳴に由来する大小感 | 母音別formant、スペクトル包絡 | target/style条件。F0と分離し、音素・話者性の崩れを確認 |
| 柔らかさ | 語頭・音の縁の柔らかな印象 | attack/release、帯域別過渡、傾斜 | 複合ノブ候補。高域を落としただけのこもりを区別 |
| 空間的な近さ | 音源が近くにいる印象 | direct/reverb比、反射、帯域形状、レベル | 出力レンダリング＋必要な発声条件。実距離cmを保証しない |
| 語りかけの親密さ | 相手に近く語りかける発声・表現 | 息、強弱、語尾、局所的prosodyの束 | style/prosodyのマクロ。音量や残響だけで定義しない |

CPPはcepstral peak prominence、HNRはharmonics-to-noise ratio。これらは主に診断・補助監督用であり、製品画面で理解を必須にしない。無声・囁きではF0や倍音に基づく量が未定義または不安定になるため、欠測と信頼度を保持し、有声向け目標を強制しない。

### 4.1 距離感を二つに分ける理由

「遠い声を大きくした音」と「耳元で語りかける声」が同じになるとは仮定しない。空間的な手掛かりと発声の仕方を別に制御し、上位の「距離感」ノブが必要に応じて両方を動かす。

音響的な距離知覚にはレベル、スペクトル、残響などが関わり、その利用は条件に依存する。室内の実験でも、主に全体レベルが判断を支えた結果があるため、direct/reverb比一つを万能な近さ指標にしない。[Sound Spectrum Influences Auditory Distance Perception, 2017](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2017.00969/full)

初期実装候補は、monoを維持した因果EQ・直接音／反射音の制御と、学習した親密な発声条件。バイノーラル・左右位置・受信側個別レンダリングは別途検証する拡張とする。

距離の評価では、音量差そのものを含む意図した再生と、音量を整合した診断比較を分ける。音量整合だけで評価すると距離手掛かりを消す場合があり、無整合だけでは「大きい方が良い」を誤認し得る。

### 4.2 「喉の鳴り方」を一つの粗さノブにしない

最初は「息」「芯・張り」「きしみ」「響き」を別候補にする。「喉」という日常語がどの音を指すかは、オーナーの選んだ基準音で合わせる。必要なら軸を統合・改名する。

望むきしみと、生成器のバリバリした破綻は、同じ粗さ指標で増加する可能性がある。イベントの位置、持続、強さ、文脈と人間の選択を使い分ける。roughnessを一律に最小化する設計は、望む表現まで消すおそれがある。

## 5. VC内部への接続

```text
入力音声 → content ──────────────────────┐
         → 明示prosody → 因果policy ───────┤
target参照 → voice / style / texture ──────┤
人間のノブ → 制御写像・平滑化 → 条件束 ────┤
                                         ↓
                               条件付きCFM → Y-S1 decoder
                                         ↓
                               因果な出力レンダリング → 出力
                                         ↓
                              試聴・操作・選択 → 設定保存
```

出力レンダリングで扱える音響変化と、生成時に学習が必要な発声変化を分ける。EQや残響は前者の候補、自然な息混じり発声やきしみイベントは後者の候補。後処理だけで話者性・発声を自由に変更できると約束しない。

Y-S1のlatent各次元に「息」「喉」と名前を付け、任意のベクトルを足す方法は採らない。制御は意味を持つ条件入力として生成器へ与え、出力音と人間の選択で効力を検証する。codec latentをspeaker-free contentとして学習する経路も復活させない。

制御量には、値に加えて適用区間・条件が必要となる。たとえば息は有声部と吸気で意味が違い、きしみは語尾だけに必要かもしれない。まず継続的に適用できる軸を実装し、イベント条件は後段で追加する。

語尾や間の生成は未来の文を知れない。既知の過去文脈から局所的に付与できる表現に範囲を限定し、任意の間・時間伸縮で遅延が蓄積する仕様を避ける。full-graphのp95 <30ms、失格上限50msを維持する。

ノブ変更は因果的に平滑化し、既出音声を変更しない。平滑化による操作応答時間と音声E2E遅延は別に測る。長い過去受容野や残響tailの長さを、そのまま先読み時間と数えない一方、実装のバッファ待ち・計算は台帳へ含める。

推論はRust/Candle、学習はuv環境のPyTorch。補助解析モデルは学習・評価用とし、出荷時依存にしない。新しい重みキー・制御ABIは両実装で一致させる。

## 6. どう学習させるか

ノブを追加しただけでは、生成器がその条件に従う保証はない。現在のS1-5に記録されたF0条件への弱い追従は、この問題をまず確認すべき理由である。記録の原因推定を確定事実として引き継がず、F0測定と条件経路を再検証する。

1. 実音声から音響特徴と信頼度を抽出する。まず同じ話者・近い音素条件で発声差を集め、話者差とスタイル差の混同を減らす。
2. 実音声の再構成でvoice / prosody / texture条件を与える。特定話者だけが息声であるようなデータ偏りを監査する。
3. 条件を交換・掃引し、再構成できるだけでなく、出力が指定に従うかを確認する。自然な同一内容ペアがあれば優先して使う。
4. 信頼できる領域に限定した音響補助lossと、内容保持・話者性の監督を検討する。音響指標だけで採用しない。
5. 人間の比較で知覚方向と選好を確認し、使える範囲を決める。基礎の内容・制御が成立した後に限り、最後のtexture fine-tuneを行う。

VC teacherの変換音声を教師波形にしない。実音声、同一内容ペア、意味が検証できる信号処理ペアを使う。信号処理で作った「息」等を自然な発声の正解と無条件に見なさない。

人間が選んだ生成音・設定は、まず候補探索とプリセット較正に使う。これをそのまま教師波形にして再学習する運用は導入しない。将来の選好学習は別のPROPOSED設計で、少数ラベルへの過適合、評価者差、既存の教師制約を検討する。

## 7. 再生側UX：聴くことと操作することを評価にする

初期画面では「声を選ぶ → 聴きながら調整する → 比べる → 保存する」を一続きにする。

- 基本ノブは、検証済みの少数だけを表示する。候補は近さ・息・芯・響き・抑揚。未学習の制御を効くノブとして見せない。
- 詳細では、空間的な近さと親密な発声、芯ときしみなどを分け、音の例を聴けるようにする。
- 現在値と保存したA/Bスナップショットを同じ入力の短いループで比較する。ライブ発声でも設定を試す。
- 一つの軸を試す間、他の値を固定できる。取り消しと基準設定への復帰を用意する。
- 「この設定が好き」「まだ使いたくない」を記録できる。操作理由の入力は求めない。
- 高さなど理解しやすい物理量は必要に応じて表示し、CPPなどの診断値は詳細な研究画面へ置く。

「萌え強度」は、耳で成立した複数軸のプリセットを基準から動かすマクロとして後から検討する。0→1で萌えが普遍的に増えるという意味にはしない。自然さや話者性が途中で崩れるなら、その範囲を使える連続ノブとして公開しない。

操作履歴は貴重だが、最後に止めた値が好きとは限らない。探索中の変更と明示的な採用を区別する。評価者・場面・再生機器ごとの設定を残し、全員の好みを一つの平均へ押し込めない。

固定ループによる比較は制御差を調べやすい一方、会話の身体感覚を保証しない。製品としての判定には、実際の発声で追従感と使い続けたさを確認する。

## 8. 官能評価とパラメタ化を一つの改善ループにする

人間が「何が悪いか」を答える代わりに、同じ入力で「息を少し減らした方を選んだ」という制御差分を残せる。この差分は、その人・その場面で改善する方向の手掛かりになる。

ただし、これは現在のモデルが生成できる範囲内での探索である。どの設定でも好ましい声を出せなければ、ノブの探索を続けても解決しない。表現能力、データ被覆、条件効力、基礎品質へ戻る。

| 観測 | 次に行うこと |
|---|---|
| ノブを動かしても音が変わらない | 配線、条件の無視、入力への依存を調べる |
| 指標は変わるが知覚方向が揃わない | 軸の定義、変化幅、指標の妥当性を見直す |
| 狙った方向へ変わるが好まれない | 範囲・組み合わせ・場面を調整する。軸の成立と選好を分ける |
| 好まれるが別発話で破綻する | 発声・音素の被覆とイベント条件を見直す |
| 全設定で不合格 | 基礎生成の診断へ戻る。人間へ欠点の命名を要求しない |

初期は一軸ずつ調べ、その後、息×芯、近さ×親密さなど関係する二軸の組み合わせを調べる。完全な物理的独立を要求するのではなく、他軸への影響が把握でき、人間が予想して使えることを目標にする。

## 9. 次の研究単位と判定

一度に全ノブを学習しない。最初の研究単位は「基礎変換の条件追従」と「一つの質感軸」の成立とする。

1. S1-5のF0測定・条件配線・追従を再確認する。codecは合格範囲内で固定し、codec側の問題が出た場合だけ戻る。
2. 評価用の男性入力と女声targetを固定し、通常発声、小声、息、囁きを区別した短い実音声セットを用意する。欠けたカテゴリを合格済みとしない。
3. 最初の質感軸として「息」を候補にし、低・中・高の三点を作る。距離感は生成側の親密さと出力側レンダリングを別実験にする。
4. 知覚方向、選好、受容性、内容保持、他軸への影響を確認する。方向が不成立なら多軸化しない。
5. 未使用発話で再確認し、ライブUXとfull-graph遅延を測ってから、次の軸へ進む。

比較数、話者数、許容する内容劣化、方向判断の基準、検証する設定範囲は、評価用データを確認したうえで走行前に固定する。本書では裏付けのない数値閾値を発明しない。小規模・単一評価者の結果は、その評価者と確認した範囲の成果として報告する。

保存項目は、既存A/B形式に実験仮説、入力・target・checkpoint・ABIの識別子、seed、制御値と時間変化、提示順、再生条件・gain、質問種別、回答、任意タグ、診断指標、適用区間・信頼度を追加する。指標を選ぶために使った発話と最終確認用の発話を分離する。証拠はresults配下へ置き、本書へ数値を重複転記しない。

進捗はloss低下だけでなく、「一つのノブの意味を耳で確認できた」「その操作で好まれる設定に到達した」「別発話でも再現した」「ライブで使いたいと判断された」として記録する。

- 旧gui_design.mdは [.archiveへ退役](../.archive/docs_2026-09-08/current/gui_design.md) した。本書はGUI実コードのレビューではなく、今後のUX意味論の提案であり、旧記載を現行実装の事実として引き継がない。
- READMEの「距離感」「柔らかさ」「ASMR comfort」は目的語として残し、各ノブの実体と測定可能性は本書の実験で確かめる。「comfort値を上げれば快適になる」という未検証の約束をしない。
- 高さ・息・響き等の何軸で十分か、喉の鳴り方をどの音で定義するか、個人差をどこまでプリセットで吸収できるかは未解決。
- 品質の良い再構成は、制御可能なVCの成立を保証しない。現在のcodec成果と、今後の変換・操作UXの成果を分けて扱う。

本提案の中心は、人間の感性を最後の合否判定だけに置かず、出力を操作する過程そのものへ組み込むことである。その操作と選択を研究側が検証可能な差分として受け取り、次のモデル改善へ返す。
