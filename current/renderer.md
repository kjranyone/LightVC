# 出力部(レンダラ)— 因果・CPU・48kHz の生成型 (status: PROPOSED・rev2・2026-10-02)

オーナー判断(2026-10-02): 波形を運ぶピッチ演算子は透明にならない(非因果 PSOLA でも ±4 半音の往復で PESQ 1.7〜2.6)→ 有声音の速い構造は出力部が生成し、揺らぎ・質感は分布を合わせる目的関数(GAN 型)で学ぶ。「異論無い」。全体は [a2vc.md](a2vc.md)、構音は [artic_inv.md](artic_inv.md)。

## 1. 役割と界面
変換器が出す条件から目標の声を 48kHz で作る。写し合成(目標の音声を分析した条件から目標自身を作る)で耳に合格することが、変換の耳に出す前提。
- 条件(フレーム 200fps・変換器の出力と同じ型・31 行・**0 = 無音**で固定の定数でずらす・発話の統計なし)。**分析は学習の教師側(と登録)だけで推論の経路に無い**(製品の条件は変換器が出す)ので、中心揃えの窓・ピッチ適応で作る(`training/pae.py`):
  - 包絡 = **CheapTrick**(f0 適応の窓 + 幅 f0 の平滑化 + 補償リフタ)のパワー包絡 → 128 帯 mel → log → DCT c0..c24。c0 から無音の値 √128·log 1e-5 を引く。**レベルは c0 だけが運ぶ**(rev0 の音量の行は c0 と重複し削除)。
    rev1 までの因果 log-mel の DCT24 は**ピッチを運ぶ**: 合成(鋭いフォルマント・雑音の床 −60dB)で f0 を +4 半音ずらすと 1.5kHz 未満の包絡が f0 300/400/450Hz で 18.9/27.5/28.3dB 動く(110Hz 2.5・220Hz 5.4)。CheapTrick は 3.9/5.6/2.5dB(110Hz 0.8・220Hz 3.1)。アニメ声の音域で倍音の縞が DCT24 の通過域に入るため(低域の mel 間隔 31.6Hz・c24 の周期 約 337Hz)。rev1 の「DCT24 は倍音の縞をほぼ運ばない」は誤り(変換器レビュー 1 巡目の指摘・artic_inv §1 の 0.75〜0.83 倍とも一致)。
  - log(f0/200)(無声 0)・有声。
  - 4 帯(0.3–1・1–2.5・2.5–5・5–10kHz)の**周期性** = 倍音の山(k·f0 ± 0.2f0 の最大)と谷((k + 0.4〜0.6)f0 の最小)のパワー比(dB)/30・[0, 1.5]・無声 0。rev1 の「mel − DCT24 の RMS」は f0 に対して非単調(110/220/330/400Hz で 2.0/8.2/10.0/6.0dB)なので替えた。SNR に対して単調(selftest)。
  - 構音のつまみ(声道長・母音空間・萌え)は変換器の側で包絡に効かせる(出力部は話者を知らない)。
- 励起: f0 の帯域制限パルス列 + 白色雑音(各段へ注入・周期の唯一の源)。入力の非周期成分(c_in)は元話者を運ぶ(単独で top-1 93.8%)ので使わない。
- f0 の時刻: 出力ブロック t は入力の [(t−1)H, tH) を作り、パルス列はブロック内で f0[t−1] → f0[t] を直線補間する。学習の f0(harvest・フレーム k の中心 = kH)はこの端点にちょうど揃う。**推論の f0 は変換器が出す**(変換器は因果 YIN から作り、目標は harvest の軌道。因果性は変換器の検査で担保)。

## 2. 構成(nvoc からの変更点と理由)
| 項目 | nvoc(REJECTED) | 本設計 | 理由(実測) |
|---|---|---|---|
| 引き上げ | 転置畳み込み 5·4·4·3 | **直線補間 + 因果畳み込み**(resize-conv) | 転置畳み込みはフレーム周期の構造を作る(一定の条件で変調の線 +37dB = ガビガビ)。補間 + 畳み込みは一定の入力から一定しか作れない(R0-1) |
| 活性 | LeakyReLU | LeakyReLU(**アンチエイリアス活性は使わない**) | diag_nvoc_aa20: 16k/48k 段の因果アンチエイリアスで PESQ 2.21 → 2.21・コントラスト 3.069 → 3.083 = 律速でない(nvoc.md §4.5)。**帰属の範囲**: 本設計で倍音間のジリジリが残っても、それは「活性の折り返しが未対策」の不合格であり、補間 + 畳み込みの方式クラスや界面の反証にしない |
| 条件 | 128 帯の log-mel そのもの | ピッチ適応の包絡(CheapTrick)の DCT24 + f0 + 周期性(31 行) | 変換器が出せる界面に合わせる。ピッチの権威は f0 とパルスに集める(包絡から倍音の縞を除く) |
| 学習 | 回帰 40k → GAN ≤ 80k | 診断(§4 R1)で決める: 最初から GAN か、回帰 20k の後に GAN | HiFi-GAN 系は最初から GAN・長く(V2 0.9M・250 万 step)。社内の GAN は短すぎた |
| 判別器 | MPD + CQTD(学習済み)→ MRD-log | MPD(2,3,5,7,11)+ MRD-log(新規・48kHz) | 学習済みの判別器は別の生成器を見分けない・高域盲目(memory) |

- 規模: 256ch・3.26M params・8.9 GMAC/s(Rust 1 スレッド RTF 0.313)。Rust の状態つき畳み込みは nvoc.rs を流用。補間の初期状態 x[−1] = 0(Python と Rust で同じ)。
- 時刻規約: nvoc と同じ(フレーム t の窓は左寄せで (t+1)H に終わる・出力ブロック t はフレーム ≤ t だけ・アルゴリズム遅延 10ms)。

## 3. 学習
- データ: 女声フルコーパス(index の train 全量)から**高域を持つファイルだけ**: 標本化 ≥ 44.1kHz・11.5–15.5kHz ≥ −40dB・16.5–20kHz ≥ −65dB(どちらも 2–6kHz 比)。台帳 `data/rvoc_f0/manifest.json`(`training/prep_rvoc_f0.py`)。標本 240 件で残存 実 66%・TTS 79%(落ちるのは 22/32kHz の実音声と帯域を切った TTS)。**実音声と TTS を 1:1** で引く(判別器の「本物」を高域の欠けた音や TTS に寄せない)。
- f0 = 前計算の harvest + stonemask(16kHz・5ms・オクターブ誤りと遅れのない教師側の値)。生の因果 YIN は学習に使わない(オクターブ誤り 5〜8%・窓の遅れ)。
- 区間 0.7s + 分析の余白(左右 1024 サンプル)。包絡はデータローダで CheapTrick(1 区間 約 36ms)・周期性は GPU。**先頭 200ms は損失と判別器の切り出しから外す**(受容野 174ms・区間の途中から始まる冷えた履歴を学ばせない。推論は無音 = 0 から始まるので一致)。
- 損失 = 45·多尺度 logmel L1(+ GAN の段では 1·LSGAN + 2·FM)。AdamW 2e-4(0.8, 0.99)・半減期 300k step の指数減衰(総 step によらない = 診断の 20k は本走行の先頭と同じ手順で、そのまま続けられる)。
- **評価と耳の判定は EMA(0.999)の重み**。評価は held21(実音声・nvoc と同じ集合)で、f0 = harvest(出力部の上限・判定に使う)と生の因果 YIN(製品の f0 推定に近い)の 2 通り。
- 条件の分析は教師側(非因果可)。推論の経路 = 生成器だけ(条件と励起に対して因果・先読み 0)。変換器の学習の正解も同じ分析で作る(変換器は因果の入力からそれを予測する)。

### R2: rvoc1 中止後の切り分け(`training/rvoc1_am_probe.py`・`results/rvoc1/am_probe.json`・学習なし・held21 写し合成)
rvoc1 は 100k で中止条件(300k 外挿 2.976 < 3.2)により停止。PESQ 2.74・hf −1.04・コントラスト 3.324・f0 権威 11.9 は通ったが、フレーム周期(200Hz)の変調の線が +0.52(40k)→ +1.47(70k)→ +2.00(100k)と増えた(本物 +0.11・必要条件 ≤ 1)。
| 重み | 線(平均 dB) | 帯域 2–4/4–8/8–12k | 条件の全行を平滑 | 包絡行だけ | f0・vuv だけ | 周期性だけ | 因果平滑(全行) |
|---|---|---|---|---|---|---|---|
| A 回帰 20k | 0.26 | .05/.64/.08 | 0.11 | 0.11 | 0.25 | 0.26 | 0.03 |
| B GAN 20k | 0.03 | −.10/.46/−.27 | −0.01 | 0.00 | 0.03 | 0.03 | −0.20 |
| rvoc1 70k | 1.47 | 1.49/1.11/1.82 | −0.02 | −0.02 | 1.47 | 1.48 | −0.10 |
| rvoc1 100k | 2.00 | 2.07/1.39/2.55 | −0.05 | −0.03 | 2.00 | 2.01 | −0.08 |
平滑 = 条件にフレーム方向の [0.25, 0.5, 0.25](対称は診断専用・因果は 1 フレーム遅れ)。
読み:
1. 線は**全帯域**に出て、増えるのは GAN の学習が進むとき(同じ重みの B 20k は 0.03)。
2. **包絡の行(c0..c24)をフレーム方向に平滑するだけで消える**(2.00 → −0.03)。f0・有声・周期性の行は寄与なし。因果な平滑(先読み 0)でも消える。
3. つまり G は包絡の**フレーム間の段差・ゆらぎ**を 200Hz の振幅変調として増幅する方向へ学習した(GAN の項が、フレームごとに独立な CheapTrick の読みの揺れを「本物の変調」として拾えるため)。回帰では起きにくい(A 0.26)。
4. 帰属の範囲: 判別器の高域盲目や PESQ の頭打ちの原因とまでは言えない。PESQ 2.74 は別問題として残る(容量・構成)。
次の改訂(rev3)の候補は、(a) 包絡の条件を学習・推論の双方で因果の平滑(EMA 等)に通す: 界面の定義を変えるので、変換器側の目標(C3)も同じ平滑を前提にする、(b) 学習時に包絡へフレーム独立の揺れを足して G を不変にする(分布側の遮断・design_laws)。(b) は推論路を変えず、(a) は包絡の時間分解能を落とす。PESQ の頭打ちを同時に直す必要があるので、容量・構成の診断(R3)の後に決める。

### R3-0: PESQ の頭打ちの帰属(`training/rvoc1_floor_probe.py`・`results/rvoc1/floor_probe.json`・学習なし・rvoc1 100k・held21・f0 = harvest)
- 励起の乱数の種だけ変えた 2 出力の間: PESQ **4.39**・logmel 0.14。元音声との PESQ 2.74・logmel 0.46。→ **乱数が上限をつくっているのではない**(出力はほぼ決定的で、不足は条件から決まる構造の側)。
- 学習の logmel(0.417・95k 付近・実と TTS の混合)と held21(0.460)の差は 0.04 で、両方ともまだ下がっている(PESQ_h は 10k あたり +0.02・log(step) 直線)。→ **汎化の問題ではなく学習の途上**。
- 容量は上げられない: 変換器・F1・C1 と合計で RTF < 0.6(converter.md C0-4)で、出力部は 256ch の 0.313 が既に約半分。MAC は 4 段にほぼ均等(各段 2.1・2.1・2.1・1.6 GMAC/s)で、偏りを直す余地もない。→ 手段は容量でなく**条件の分布と学習手順**。
- 条件の包絡行を因果平滑して(未適応の重みに)入れると PESQ 2.74 → 2.54・logmel 0.46 → 0.55・線 +2.00 → −0.06。(1 フレーム遅れの分を含むので、適応後の費用は別に測る。)
- 以前の記述「f0 を YIN にすると PESQ 1.67」は、製品の f0 の経路(F1)の値ではない: F1(f0est2)の写し合成は 2.4745 で、同じ重み(diag_rvoc_r 20k)の harvest 2.507 に近い(0.03 差)。
- 推論の条件(変換器が出す包絡)はなめらかで、学習の条件(CheapTrick の読み)はフレーム間のゆらぎを含む = 分布が違う。そこで教師側(中心窓・先読みあり)で [.25,.5,.25] を平滑する界面 rev3(a')を検証する: `results/diag_rvoc1s`(rvoc1 100k から +10k・prereg 済み)。

### R3-2: 幅の診断(`results/diag_rvoc_g384`・B と同じ手順・無平滑・20k)
- 384ch(20.0 GMAC/s = 2.25 倍): PESQ_h 5k/10k/15k/20k = 2.110/2.400/2.513/2.579(B 256ch: 1.905/2.235/2.361/2.432)・logmel 0.482(B 0.518)・線 −0.10・hf −1.49・contrast 3.337。差 +0.15 は 5k〜20k でほぼ一定 = **幅は PESQ の伸びに効く**(天井か速さかは 20k では分けられない)。
- 384ch は RTF の予算(出力部 0.313・合計 < 0.6)に入らない → MAC を 256ch と同程度に保って幅を稼ぐ構成を診断: `diag_rvoc_w1`(384ch・カーネル (3,7)・拡張 (1,3)・8.14 GMAC/s)・`diag_rvoc_w2`(384ch・(3,7,11)・拡張 (1)・8.42 GMAC/s)。
- F1 の偽有声(`results/f0est2/false_probe.json`): 女声 held21 で harvest・pYIN がともに無声のフレーム 9,384 のうち F1 が有声と言うのは 10.9%。そのうち有声区間の端から 4 フレーム以上離れた孤立が 73%・連続長の中央値 2 フレーム(58% が 2 フレーム以下)・音量は発話最大の中央値 −27.5dB(無音ではない)= 摩擦音・息の区間で一瞬だけ有声と言う型。レンダラーに入ったときの害は未測定。

### R4: 耳の較正(`results/earbattery/rvoc_ab`・順位式・2026-10-04・n = 3 試行)と高い声の層別
- 刺激: 元音声・BigVGAN v2(錨)・rvoc(`diag_rvoc1s` 110k の EMA・PyTorch・f0 = harvest・包絡は元音声の分析)・held21 のうち有声率の高い 3 発話。形式は**順位式**(1 位 = 良い)で、事前に私が書いた「合格/不合格」は誤記。
- 結果(鍵で開封): rvoc_05(PESQ 3.18): 元音声 > **rvoc** > BigVGAN / rvoc_06(2.95): **rvoc** > 元音声 > BigVGAN / rvoc_08(2.33・f0 中央値 591Hz): BigVGAN > 元音声 > **rvoc**。オーナー所見: rvoc_08 は「叫びの演技が学習データに無く劣化したかも」。
- 読み: (1) rvoc の PESQ 2.95 が元音声と BigVGAN(3.98)より上に順位付けされた試行がある = **PESQ ≥ 3.2 の必要条件は耳に対して較正されていない(厳しすぎる線)** → 耳へ出す必要条件から PESQ の絶対値を外し、変調の線(≤ 1)・hf・コントラスト・f0 の権威と、後述の f0 層別を残す。(2) n = 3・順位だけ・Rust 経路ではない音 → 採用の根拠ではなく、PESQ の線の較正と弱点の特定に使う。
- 弱点(層別): held21 の f0 中央値と logmel の相関 0.68(PESQ −0.46)。<450Hz(n=9)logmel 0.415/PESQ 2.96 に対し ≥490Hz(n=9)0.523/2.41(`results/diag_rvoc1s/f0strat.json`)。学習の混合は区間の f0 中央値 450Hz 以上が約 25%・550Hz 以上が 11% で、held21(57%・24%)の半分以下。rvoc_08 は f0 の 10〜90 パーセンタイルが 469〜740Hz。叫びかどうか(音量・声の張り)は音量が他と同程度で断定できない。製品の声(アニメ声)は高い f0 が中心なので、全体の平均でなく高い群で測る。
- 検証: `results/diag_rvoc1f`(f0 の分布を寄せて +10k・prereg 済み)。PASS = 分布の偏りが主因・FAIL = 高い f0 での条件の情報不足(界面の診断へ)。

### R5: 高い声の差の帰属(学習なし・`f0strat_probe.py`・`f0refine_probe.py`・`f0strat_band_probe.py`・`results/*/f0strat*.json`)
差 = 高(f0 中央値 ≥ 490Hz・n = 9)− 低(< 450Hz・n = 9)の logmel / PESQ_h(held21・f0 = harvest)。
| 重み | 低 logmel | 高 logmel | 差 | PESQ 差 |
|---|---|---|---|---|
| B 256ch 20k(無平滑) | 0.462 | 0.580 | 0.118 | 0.657 |
| g384 20k | 0.427 | 0.542 | 0.114 | 0.649 |
| W1 20k | 0.463 | 0.580 | 0.116 | 0.623 |
| 回帰 A 20k(pae) | 0.442 | 0.559 | 0.117 | 0.708 |
| mel 条件 C 20k | 0.446 | 0.546 | 0.101 | 0.624 |
| rvoc1s 110k | 0.415 | 0.523 | 0.108 | 0.554 |

- 差は幅・学習の長さ・f0 の寄せ・条件の種類でほぼ動かない。教師の f0 が外れているせいでもない(櫛による補正は両群とも 17cent・補正しても logmel は変わらず)。BigVGAN(非因果・1 億パラメータ超)には差がほぼ無い → 評価の指標や発話の性質ではなく、この規模の因果レンダラーに固有の弱点。
- 高い群の有声フレームは高域が出すぎ(出力 − 元の log-mel のバイアス: 2.5–5k +0.15・5–10k +0.23・10k 以上 +0.54・低い群は +0.01/+0.06/+0.32)。倍音の山谷(周期性の 4 帯は 10kHz まで・10kHz 以上の周期情報は条件に無い)と高域の包絡の分解能が候補だが、未検証。
- 扱い: 製品の声は高い f0 が中心なので、評価を f0 層別で常に併記し、rvoc2 の成功条件に高い群の logmel の改善を入れる。界面の拡張(高域の周期性帯・包絡の分解能)は rvoc2 の結果と変換器側のレビューの後に診断する。

### R7: 耳(`results/earbattery/rvoc_ab2`・rvoc2am2 の 300k・n = 3・順位式)と f0 の上限(2026-10-05)
- rvoc2am2 300k(最後の 3 回: 線 0.14・PESQ_h 2.79・logmel 0.4535・hf −0.93・contrast 3.360・f0auth 12.7)。耳: rvoc_05: rvoc > 元音声 > BigVGAN / rvoc_06: 元音声 > BigVGAN > rvoc / rvoc_08: BigVGAN > 元音声 > rvoc。オーナー: 「全体的には良くなってる」・rvoc_08 の「頭出しのハイトーンがまだ崩壊する」。(110k: 05 は 2 位・06 は 1 位・08 は 3 位 = 順位 3 試行はぶれが大きく傾向は言わない。)
- rvoc_08 の頭出しの原因: 始動の状態でも(無音を先頭に付けても同じ)音量の範囲でも(入力を −18dB まで下げても差 −8.4dB で一定)ない。最初の約 0.5 秒は **1.01〜1.07kHz の安定した高音**(500Hz 以下は −50〜−63dB)で、教師の harvest の f0 上限 1000Hz を越え、無声または誤った 229〜263Hz と判定される。出力は 1〜2.5kHz で 10〜20dB 足りない。
- f0 の上限 1000Hz は 4 か所: 教師(prep_rvoc_f0.py・train_rvoc.harvest_frames・prep_f0est.py の f0_ceil)・F1 の入力(CMNDF の最短の遅れ 48 サンプル = 1kHz)・F1 の出力(分類 50〜1100Hz)。励起 harmonic_source は上限なし。
- 実データでの頻度: held21 の有声フレームの 0.77% が 1kHz 超(この発話 7.9%・他は 2.1% 以下)。男声→女声の変換では元の f0 が +4〜12 半音動くので、男声の叫びは 1kHz を越えうる。
- 上限を 1500Hz に上げた harvest の試験: 1000Hz 以下のフレームの 99.07% が 50cent 以内で一致・**新しいオクターブ上誤りが 0.35%**(得る 0.77% と同程度)。単純な上限引き上げは不可。必要: オクターブ誤りの除去(連続性・pYIN の裏取り)を入れた教師の作り直し → renderer 用データ(約 3 時間の CPU)・F1 の学習データ・F1 の再学習・renderer の追い学習。
- 扱い(私の判断): 変換器の同一性(いまの最大の未達)を先に進め、f0 の上限の拡張は並行の課題として登録する。出力部の ADOPTED 候補化は『上限 1000Hz 以内では耳で通る』として扱い、1kHz 超の叫びは未対応と明記する。製品の範囲(叫びをどこまで)はオーナーに確認する。

### R8: 1kHz 超の対応と耳(2026-10-05・rvoc3hi 330k)
- 学習: rvoc2am2 300k から +30k(`results/rvoc3hi`・f0 = f0hi の教師・p_hi 0.05・両方向の線の罰則)。通常の評価は後退なし(PESQ_h 2.804 → 2.836・logmel 0.4514・線 0.2・hf −0.97)。

- 耳(rvoc_ab3・n = 4・順位式の記録なし): オーナー『全部問題なさそう』(rvoc_08 の頭出しのハイトーンを含む)。
- 状態: 出力部を **ADOPTED 候補**(PyTorch の音で確認済み)。残り: Rust の書き出しと一致検査(R0-3 の続き)・変換器の C3 の出力部として通す・1kHz 超の通し(F1 の f0 → 出力部)。

## 5. 到達見込みと中止条件(design_laws §3-7・コードで自動)
- 前例: 社内 nvoc(3.4M・因果)の写し合成 PESQ は回帰 160k で 3.09(ブザーで耳 FAIL)・GAN 80k で 2.25(ブザー +1.7dB・耳未試験)。耳の較正は PESQ 2.96(Y-S1 往復・FAIL)/ 4.10(BigVGAN・PASS)、PESQ 3.47 でも耳が拒否した例あり(memory pesq-gain-ear-rejects)。
- 中止条件(`train_rvoc.tripwire`・`diag_` 以外で自動・`STOP.json` を書いて終了): 20k < 2.0・40k < 2.4・100k < 2.5・100k 以降で変調の線 > 3dB・100k 以降で 40k からの log(step) 外挿が 300k で < 3.2・300k < 3.2。prereg.yaml が無ければ起動しない(コードで強制)。
- 耳へ出す必要条件(写し合成・元音声と並べた合否・EMA の重み): 変調の線 ≤ 1dB・hf ≥ −1.5dB・f0 の権威 ≤ 20 cent・倍音間コントラスト ≥ 3.15 に加え、
  - 回帰だけの重み: PESQ_h ≥ 3.6。
  - GAN の重み: PESQ_h ≥ 3.2(GAN は耳の質を上げながら PESQ を下げうる: memory frame-rate-buzz-pesq-blind)。**3.2〜3.6 の GAN の重み**は、同じ step の回帰の重みより変調の線とコントラストで明確に良い(線 −1dB 以上・コントラスト +0.03 以上)場合だけ耳へ。
- 見積もり: GAN 0.39 s/step(単独)× 300k = 約 1.4 日。
