# 研究の計画法(正典・2026-10-18 rev0)

オーナー指摘(10-18):「いつまでも進捗が無いのは？ML における計画法とかあるでしょ」「計画法を正しく定義して」。
拠り所: Andrew Ng『Machine Learning Yearning』/ Structuring ML Projects(単一の評価指標・最適化指標と満足指標・開発と試験の組・誤差の分析・データの食い違い)、Karpathy『A Recipe for Training Neural Networks』(骨格と単純な基準を先に・小さく過学習させてから広げる)、Google『Deep Learning Tuning Playbook』(仮説ごとの段階的な改善・試行の回転数)、Google『Rules of ML』(最初のモデルは単純に・評価の仕組みを先に)。本書はそれをこのプロジェクトの制約に合わせて手順に落としたもの。

## 1. 用語
- **最適化指標**: 改善を判定する唯一の数値。
- **満足指標**: 閾値を満たせばよい数値(超えた分は評価しない)。
- **基準(ベースライン)**: 成績表の 1 行。新しい手はすべて同じ評価で基準と比べる。
- **反復**: 1 つの仮説を 1 回試して、採用 / 棄却 / 保留を決めるまで。
- **進捗**: 成績表の最適化指標が、測定のぶれ幅(目標でまとめたブートストラップの 95% 区間の半幅)を超えて良くなること。それ以外は進捗と呼ばない。

## 2. 評価の仕様(作業の前に固定・変えるときは版を上げてオーナーに報告)
| 項目 | 定義 |
|---|---|
| 最適化指標 | **男声 → 女声の v1⊥ の決定値の中央値**(dev 3 組 × 60 組・`training/eval_v1perp.py`・低いほど良い)。到達の線 = AUC ≤ 0.95(耳で合格した写し合成の水準) |
| 補助(同じ方式) | 女声 → 女声の v1(devff)・自己変換の v1(写し合成の床) |
| 満足指標 | 本人らしさ: 声域の中心の LDA と ECAPA で kNN-VC との順位差の点推定 ≤ 0 かつ 95% 上限 ≤ +1.0(オーナー 10-15)/ CER ≤ 製品の基準 + 0.03 / 出荷ゲート(未来不変性・遅延 < 30 ms・計算の台帳) |
| 組 | 学習 = 全量のコーパス(評価の話者を除く)/ 開発 = dev・dev2・dev3(男声 → 女声)+ devff(女声 → 女声)/ 試験 = eval2(一度だけ・最終判定) |
| 参照点 | 本物の音声(到達の上限)・写し合成(系の天井)・kNN-VC(外部の基準)・今の製品(G03S10ZH) |
| 耳 | 最終の受け入れだけ(解析の線を通った候補のみ) |

## 3. 手順
### 段 0: 評価の仕組み(済み・10-18)
v1 / v1⊥・開発の組・成績表(`results/LEADERBOARD.md`)。

### 段 1: 端から端までの基準を作る(最初に必ず)
- 推論と同じ入力で学習する骨格を 1 本作り、評価の仕様で測って成績表の 1 行目にする。部品を個別に磨くのはこの後。
- **学習と推論の一致の規則**: 学習する部品は、推論で受け取る入力の分布で学習する(上流の推定・変換を学習の中で再現する)。教師の条件で学習して推定の条件で使う、を禁止する。
- 確認の順: 小さい組で過学習できる(写し合成が教師並み)→ 全量へ広げる。

### 段 2: 反復(1 反復 = 1 仮説)
1. **誤差の分析**: 今の最良の系で、開発の組の発話を v1⊥ の悪い順に並べ、悪い 30 本を失敗の型に分類する(解析の札: 無音の雑音・包絡の動き・周期性・高さ・内容の崩れ・本人らしさ など)。型ごとに「直したら最大どれだけ良くなるか」を、本物の値への差し替え(oracle)で見積もる。
2. **仮説の選択**: 期待される改善 × 当たる見込み ÷ 費用 が最大のものを 1 つ選ぶ。
3. **事前登録**(`results/<tag>/prereg.yaml`): 仮説・変更・期待する効果の大きさ・最も安い途中の信号・打ち切りの閾・時間の区切り・設計三層則 L / I / C。
4. **見当づけ**: 20〜30 組・最適化指標だけ・**10 分以内**(学習は最初の確認まで 1 時間以内)。
5. **確認**: 見当づけで基準より良ければ、60 組 × 3 組・満足指標を測る。
6. **判断**: 進捗(§1)なら採用して新しい基準に。そうでなければ棄却として成績表に記録。
7. 同じ型の棄却が 2 回続いたら、仮説の層を替える。

### 段 3: 到達と受け入れ
開発の組で到達の線と満足指標を通ったら、試験の組で一度だけ判定 → 耳 → 製品の経路(Rust・出荷ゲート)。

## 4. 運用
- 成績表 `results/LEADERBOARD.md`: 全ての反復の 1 行(日時・構成・最適化指標と区間・満足指標・判断・証拠のパス)。
- 時間の区切り: 各反復の開始時に完了の時刻を宣言し、過ぎたら打ち切る。
- 報告: 反復ごとに成績表の差分。1 日 1 回、到達の線までの距離と次の反復を報告。
- 計画の見直し: 3 反復続けて進捗が無ければ、段 1 の基準そのものを見直す(オーナーに報告)。

## 5. これまでの逸脱(10-18 の自己点検)
- 最適化指標を固定せず、耳と合わない代わりの指標(LDA・d109 の軸・CER)を何週間も最適化した(§2 に違反)。
- 端から端までの基準を作らず、部品を個別に磨いた(§3 段 1 に違反)。
- 出力部を教師の条件で学習し推定・変換の条件で使った(学習と推論の一致の規則に違反)。
- 誤差の分析をせず仮説に飛んだ・1 反復 20〜60 分を直列に回した(§3 段 2 に違反)。
