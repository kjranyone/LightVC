# 設計三層則と起動前検査 L/I/C

> status: 規範（プロセス規則・全学習腕に即時適用）。2026-09-20制定。
> ネットワーク設計ではないため PROPOSED/ADOPTED の昇格対象外。改訂は§6の規則による。
> 根拠: 2026-09の負例群（F0権威7負例・s8/s9容量無効・CFM平均退化・NSF v1チート/v2停滞→s3で分布側介入が即時発現）。個別証跡は [RESEARCH.md](RESEARCH.md) / [FAILURE_NOTES.md](FAILURE_NOTES.md)。
> 本書は reasoning 資源の少ないエージェントでも機械的に運用できるよう、判断を記入式に落としてある。**読まずに学習を起動してはならない。** Shipping Gate（遅延・因果・RTF）への追加であり代替ではない。

## 0. 三層則（暗記事項）

1. **配線（アーキテクチャ）が決めるのは「何が表現可能か」だけ。学習が収束する先は、損失の解析的最適解と、学習データ分布上の識別可能性が決める。** 設計意図は回路図ではなく、損失とデータ分布に書く。
2. **情報が冗長なとき、モデルは設計者が意図した入力ではなく「最も読みやすい」入力を使う。** 条件に権威を持たせたければ、その情報の供給源を学習分布上で唯一にする。
3. **構造的禁止は意図しない解を消すだけで、意図した解へ導かない。** 意図した解を「可能」にするのではなく「最もラクな解」にする。禁止だけの設計は停滞する（NSF v2実測）。

系: 本プロジェクトで実際に効いた介入は全て データ分布・ペア構成・目的関数 の層にある（f0fix・補間CFM化・mel条件追加・s3不変性正則化）。容量・幅・深さ・条件concatは、検査Iを通らない限り無効（s8/s9/f0h×2で実測済み）。

## 1. 起動前検査（全学習腕で必須・記入式）

学習を起動する前に、以下の3検査を§4のテンプレートへ記入し `results/<tag>/prereg.yaml` に保存、学習ログ先頭にそのパスを残す。
**1つでも記入できない・FAILのまま埋まらない場合は起動しない。「走らせて様子を見る」は禁止。** 埋められない場合は、記入済み部分と詰まった箇所を添えてオーナーへ停止報告する（§3-5）。

### 検査L: 損失最適解の書き下ろし

1. この損失の大域最適解を数式または1文で書き下ろす（例:「z0とz1が独立なL2回帰の最適解は E[z1|c]」）。
2. targetへの写像が一対多で損失がL1/L2なら、最適解は条件付き平均。**平均化で消える微細構造を名指しする**（例: 包絡微細構造・位相・息のtexture）。
3. 消える構造が耳に必要なら FAIL。認められる対処は (a) 決定条件の追加（s11型）、(b) 分布型目的関数（補間CFM＋multi-step）、(c) 規則の範囲内のGAN texture FT。**loss重みの調整は対処ではない。**

### 検査I: 識別可能性監査

権威を持たせたい各条件について、次の表を埋める。

| 条件 | 権威を持たせたい情報 | 同じ情報を運ぶ他入力（学習分布上） | 分布レベルの遮断手段 |
|---|---|---|---|
| 例: lf0 | pitch | mel倍音・ContentVec | 条件抽出前の音声を摂動しmel/content側のpitchを嘘にする |

- 「同じ情報を運ぶ他入力」が空でない行に遮断手段が無ければ **FAIL**。
- 遮断手段は**分布レベルに限る**: 入力摂動・ペア構成・条件ドロップ・不変性正則化。配線レベル（ゲート・帯域制限・concat位置）だけでは不十分（NSF v2停滞・s13負例）。
- **摂動は入力（条件抽出前の音声）側に置く。target側に置かない**（s12負例: シフタのアーチファクトが教師に入り包絡12.7dB崩壊）。教師は実音声（またはそのGT latent）を維持する。
- 機械的確認: 線形プローブ（他入力から当該情報が読めるか）とオラクルスワップ（当該条件だけ差し替えて出力が動くか）を0-GPUまたは既存ckptで**学習前に**実施し、結果と証跡パスを記入する。`training/diag_cfm_audit.py` の流儀を事前に回すだけでよい。

### 検査C: 怠惰な悪魔テスト（チート列挙と最ラク性）

1. 「この損失を最もラクに下げる方法」を敵対的に最低3つ列挙する（例: 条件の恒等コピー、事例分布の平均出力、別入力からの情報再構成、無声化・無音化による損失回避）。
2. 各チートが**分布レベルで**塞がれているかを書く。配線でしか塞がれていない場合は停滞リスクを明記する。
3. 最後に1文で「**意図した解がこの損失地形で最もラクな解である理由**」を書く。書けない場合はFAIL — NSF v2型の停滞をする見込みが高い。分布側の誘導（不変性正則化・ペア構成・カリキュラム）を足してから再記入する。

## 2. 負例対応表（本則の実測根拠・パターン照合用）

新しい腕を設計するときは、まずこの表から最も近い型を探し、同じ轍を踏んでいないか確認する。

| 型 | 事例 | 何が起きたか | 違反した検査 |
|---|---|---|---|
| 条件付き平均退化 | s1〜s6 CFM（v(z0,t)学習） | z0独立のL2最適解=E[z1\|c]でblur。ネットは完璧に「正解」に収束した | L |
| 冗長条件の中和 | s10/s12/s13/f0h×2/NSF v1・v2（F0権威7負例） | 学習分布上lf0は常にmel倍音・ContentVecと一致=読まなくても損失が下がる→無視 | I |
| 容量で識別可能性は直らない | s8(spk_in)/s9(dim512) | 条件経路強化・容量倍増が無効。問題は容量でなく供給源の唯一性 | I |
| content leak | s7/s8 話者cos床0.30 | (content,speaker)が常に一致ペア→identityをcontent側で説明、speaker条件は放置 | I |
| 条件が全部を運ぶ | s11 mel_in | 包絡は解決したがsource話者性とpitchも供給→F0制御消滅・変換と構造的に衝突 | I |
| チートの即時発見 | NSF v1 | 構造が許した抜け道（位相含有マスク×キャリア）を最適化が必ず見つける | C |
| 禁止だけで停滞 | NSF v2 | チートは封じたが意図解が険しく品質0.66停滞・掃引不成立 | C（最ラク性欠如） |
| 正しい適用 | s3 | 分布（f0シフトペア不変性正則化）で意図解を最ラク化→掃引権威がsmokeで即時発現 | — |
| データに関係が無い | f0破損85% | 雑音条件は無視するのが最適解。学習は「正しく」進んだ | （データ検証） |

## 3. 禁止事項（ハードルール）

1. 検査IのFAILに対して、容量・幅・深さ・条件concat・loss重み調整を対処として提案しない。
2. 「構造で禁止したので学習すれば意図通りになる」と書かない。禁止の後に必ず最ラク性の根拠（検査C-3）を書く。
3. 冗長な条件を残したまま、その条件に権威を持たせる腕を起動しない（lf0系3負例＋F0権威7負例で確定）。
4. 摂動・シフト等の人工データをtarget側に置かない。教師は実音声を維持する。
5. 検査が埋められない・判断に迷う場合は起動せず停止報告する。**停止はペナルティではない。無検査の起動が事故である。**
6. forkのPASSとFAILが同じ次行動になる腕（結果が次の判断を変えない腕）は情報価値ゼロなので起動しない。

## 4. 事前登録テンプレート（腕ごとにコピーして記入）

```yaml
arm: <tag>
date: <YYYY-MM-DD>
hypothesis: <1文>
scoreboard_axis: <この腕が動かすと宣言する軸（話者cos/CER/包絡/F0掃引/レイテンシ/耳）>
check_L:
  loss_optimum: <解析的最適解を1文>
  averaged_out: <平均化で消える構造 / なし>
  remedy: <(a)条件追加 (b)分布型目的 (c)GAN-FT / 不要>
check_I:
  table:  # 権威条件ごとに1行
    - {cond: <条件>, authority: <情報>, leaks_from: [<他入力>], blocked_by: <分布レベル遮断手段>}
  probes: <線形プローブ/オラクルスワップの結果と証跡パス>
check_C:
  cheats: [<チート1>, <チート2>, <チート3>]
  blocked_at: [<分布/配線>, ...]
  easiest_path: <意図解が最ラクである理由1文>
success: <合否閾値（数値・走行前固定）>
fork: {PASS: <次の行動>, FAIL: <次の行動>}   # 同一なら起動しない
tripwire: <step Nでの自動中止条件（例: step5kでsweepが±X半音に入らなければabort）>
```

## 5. 記入例（参考: 統一摂動腕を書いた場合）

```yaml
arm: s14_perturb_cfg
date: 2026-09-20
hypothesis: 条件抽出前音声へのpitch+フォルマント+EQ一括摂動で、lf0とspeaker条件だけが真実の供給源になり、F0権威とcontent leak遮断が同時に成立する
scoreboard_axis: F0掃引誤差・話者cos_vs_target・包絡MAE
check_L:
  loss_optimum: 補間CFMの速度場回帰。K-step samplingで条件付き分布から抽出（平均退化なし=s7で実証済み）
  averaged_out: なし（s11相当のmel条件で包絡は決定される）
  remedy: 不要
check_I:
  table:
    - {cond: lf0, authority: pitch, leaks_from: [mel倍音, ContentVec], blocked_by: 摂動でmel/content側pitchが嘘になる}
    - {cond: speaker_emb, authority: identity, leaks_from: [mel包絡, ContentVec話者リーク], blocked_by: フォルマント摂動でmel/content側identityが嘘になる。条件ドロップ+CFGで強度制御}
    - {cond: mel_in(摂動後), authority: 包絡微細構造, leaks_from: [], blocked_by: 不要}
  probes: 摂動後melからのlf0線形プローブR²と、摂動前後ContentVecの話者cosを学習前に測って記入
check_C:
  cheats: [mel倍音からpitch再構成, content話者リークからidentity再構成, 事例分布平均の出力]
  blocked_at: [分布（摂動で倍音が嘘）, 分布（摂動でフォルマントが嘘）, 目的関数（補間CFM）]
  easiest_path: 摂動下で損失を下げる唯一の一貫した説明が「pitch=lf0・identity=speaker_emb・包絡=mel」の割当だから
success: 学習規約内F0掃引±0.5半音・女声source cos_vs_target≥0.40・包絡≤4.0
fork: {PASS: 男声source混入とK蒸留へ, FAIL: 摂動強度の掃引1回のみ→それでもFAILならcodec契約変更(s3系)へ}
tripwire: step5kでF0掃引が±3半音に入らなければabort
```
